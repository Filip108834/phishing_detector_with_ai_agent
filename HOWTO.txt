================================================================================
  PHISHING DETECTOR WITH AI AGENT
  Pełny przewodnik uruchomienia - od zera do wyników kampanii
================================================================================

  Opis projektu:
    System laboratoryjny do wykrywania phishingu. Składa się z:
      - GoPhish        - platforma symulacji kampanii phishingowych
      - MailHog        - fałszywy serwer SMTP/skrzynka odbiorcza (lab only)
      - PostgreSQL     - baza danych predykcji
      - Agent AI       - FastAPI + ML pipeline (spaCy + TF-IDF + Ensemble)

  Wymagania wstępne:
      - Docker Desktop  (https://www.docker.com/products/docker-desktop/)
      - Python 3.11+    (https://www.python.org/downloads/)
      - Git             (https://git-scm.com/)
      - min. 4 GB RAM wolne dla Dockera

================================================================================

[ PRZEGLĄDARKA ]

  2. Zaloguj się:
       Login:    admin
       Password: <hasło z logów>
  3. System poprosi o zmianę hasła - ustaw nowe i zapisz je.
  4. Po zalogowaniu kliknij ikonę osoby (prawy górny róg) → "Account Settings"
  5. Skopiuj wartość pola "API Key"

  GOPHISH_API_KEY=<wklejony_klucz_api>

  docker compose restart ai-agent

================================================================================
  KROK 10 - URUCHOMIENIE KAMPANII PHISHINGOWEJ
================================================================================

  Skrypt campaign_generator.py:
    - Tworzy profil SMTP w GoPhish (→ MailHog)
    - Tworzy szablon e-mail phishingowego
    - Tworzy stronę-pułapkę (landing page)
    - Tworzy grupę 5 testowych odbiorców (@lab.local)
    - Uruchamia kampanię
    - Eksportuje wiadomości z MailHog do data/raw/<nazwa_kampanii>/
    - Zapisuje metadata.json z etykietą "phishing"

  Dostępne szablony phishingowe:
    lab_phish_bank_alert       - fałszywy alert bezpieczeństwa banku
    lab_phish_password_reset   - wygasłe hasło Microsoft
    lab_phish_package_delivery - niedostarczona paczka (DHL/UPS)

  -------------------------------------------------------------------------
  Opcja A: JEDNA kampania (wybrany szablon)
  -------------------------------------------------------------------------

[ TERMINAL - .venv ]
  # Kampania "alert bankowy":
  python -m simulation.campaign_generator --mode phishing --template lab_phish_bank_alert --name campaign_bank_alert

  # Kampania "reset hasła":
  python -m simulation.campaign_generator --mode phishing --template lab_phish_password_reset --name campaign_password_reset

  # Kampania "paczka kurierska":
  python -m simulation.campaign_generator --mode phishing --template lab_phish_package_delivery --name campaign_package_delivery

  -------------------------------------------------------------------------
  Opcja B: TYLKO legit e-maile
  -------------------------------------------------------------------------

[ TERMINAL - .venv ]
  python -m simulation.campaign_generator --mode legit

  Wyeksportuje legit wiadomości do:
    data/raw/legit_batch_01/

  -------------------------------------------------------------------------
  Opcja C: WSZYSTKIE kampanie phishingowe + legit (domyślnie uruchamia
           jedną kampanię bank_alert + legit)
  -------------------------------------------------------------------------

[ TERMINAL - .venv ]
  python -m simulation.campaign_generator --mode all

  -------------------------------------------------------------------------
  Po uruchomieniu skryptu wiadomości trafiają do MailHog.

[ PRZEGLĄDARKA ]  Sprawdź czy e-maile dotarły do MailHog:
  http://localhost:8025
  Powinieneś zobaczyć 5 wiadomości (po jednej na każdego z odbiorców testowych).

  -------------------------------------------------------------------------
  Opcja A: Klasyfikacja kampanii z plików .eml (zalecana)
  -------------------------------------------------------------------------
  Czyta pliki z data/raw/<nazwa_kampanii>/ i porównuje z ground truth
  z metadata.json → zwraca metryki accuracy.

[ TERMINAL ]

  curl -s -X POST http://localhost:8000/ingest/campaign/campaign_bank_alert | python -m json.tool

  # Sklasyfikuj kampanię password_reset:
  curl -s -X POST http://localhost:8000/ingest/campaign/campaign_password_reset | python -m json.tool

  # Sklasyfikuj kampanię package_delivery:
  curl -s -X POST http://localhost:8000/ingest/campaign/campaign_package_delivery | python -m json.tool

  # Sklasyfikuj legit batch:
  curl -s -X POST http://localhost:8000/ingest/campaign/legit_batch_01 | python -m json.tool

    "campaign": "campaign_bank_alert",
    "classified": 5,
    "phishing": 5,
    "legit": 0,
    "errors": 0,
    "accuracy": 1.0,
    "ground_truth_available": true
  }

  -------------------------------------------------------------------------
  Opcja B: Ingest bezpośrednio ze skrzynki MailHog
  -------------------------------------------------------------------------
  Pobiera wszystkie bieżące wiadomości z MailHog i klasyfikuje.

  curl -s -X POST "http://localhost:8000/ingest/mailhog?clear_after=true" | python -m json.tool

  Opcja C: Klasyfikacja pojedynczej wiadomości (raw MIME)
  -------------------------------------------------------------------------

    | python -m json.tool

================================================================================
  ROZWIĄZYWANIE PROBLEMÓW
================================================================================

  PROBLEM: docker compose up zwraca błąd "port already in use"
  ROZWIĄZANIE:
    Sprawdź czy nie masz innej usługi na portach 8000, 8025, 1025, 3333, 5432.
    Zatrzymaj kolidującą usługę lub zmień porty w docker-compose.yml.

  PROBLEM: GoPhish loguje "Error: could not connect to SMTP server"
  ROZWIĄZANIE:
    Upewnij się że kontenery mailhog i gophish są w tej samej sieci Docker.
    Sprawdź: docker compose ps

  PROBLEM: campaign_generator.py zwraca "[BŁĄD] Brak GOPHISH_API_KEY"
  ROZWIĄZANIE:
    Uzupełnij GOPHISH_API_KEY w pliku .env (Krok 6).
    Upewnij się że środowisko wirtualne jest aktywne przed uruchomieniem.

  PROBLEM: curl http://localhost:8000/health zwraca "DB not ready"
  ROZWIĄZANIE:
    docker compose restart db
    docker compose restart ai-agent
    Poczekaj 30 sekund i spróbuj ponownie.

  PROBLEM: Model zwraca "heuristic" zamiast "ml"
  ROZWIĄZANIE:
    Wytrenuj model (Krok 8) i zrestartuj ai-agent.
    Sprawdź czy plik models/classifier.joblib istnieje.

  PROBLEM: Brak wiadomości w MailHog po uruchomieniu kampanii
  ROZWIĄZANIE:
    1. Sprawdź logi GoPhish:  docker compose logs gophish
    2. Sprawdź połączenie GoPhish → MailHog:
       http://localhost:3333 → Sending Profiles → Sprawdź profil SMTP
    3. Upewnij się że GOPHISH_API_KEY jest poprawny.

  PROBLEM: Błąd "No such container" przy docker compose exec
  ROZWIĄZANIE:
    docker compose up -d

  PROBLEM: pip install zwraca błędy kompilacji (lxml itp.)
  ROZWIĄZANIE: Windows:
    Zainstaluj Visual C++ Build Tools:
    https://visualstudio.microsoft.com/visual-cpp-build-tools/
    Lub użyj: pip install --only-binary :all: lxml

  PROBLEM: Błąd PowerShell "cannot be loaded because running scripts is disabled"
  ROZWIĄZANIE:
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

================================================================================
  ENDPOINTY API - SKRÓCONA ŚCIĄGAWKA
================================================================================

  GET  /health                              - status agenta i modelu
  GET  /model/info                          - szczegóły załadowanego modelu
  GET  /poller/status                       - status pollera MailHog

  POST /predict                             - klasyfikuj (JSON: sender/subject/body)
  POST /predict/raw                         - klasyfikuj surowy .eml (JSON: raw_eml)

  POST /ingest/mailhog?clear_after=false    - pobierz z MailHog i klasyfikuj
  POST /ingest/campaign/{name}             - klasyfikuj z data/raw/{name}/
  DELETE /ingest/mailhog/purge             - wyczyść inbox MailHog

  GET  /results                             - lista predykcji (filtry: label, campaign)
  GET  /results/stats                       - zagregowane statystyki
  GET  /results/{id}                        - szczegóły predykcji
  GET  /results/campaign/{name}            - predykcje danej kampanii
